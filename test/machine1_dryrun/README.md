# Machine 2 synthetic dry-runs and interactive test windows

Harnesses used to verify the Machine 2 (28-state) changes without a PLC, camera or QR scanner.
All need Redis on localhost:6379; the DB ones need PostgreSQL on 127.0.0.1:5432 (postgres/postgres).
Run from a scratch directory: image files are written under `C:/AshokLeylandImages/...` relative to it on non-Windows.

| Script | What it exercises |

| `DryRun_IOServer_Two_Full_Cycles.py` | Real `costhetaio/commonplc/PLCIOServer.py` with a simulated PLC under the real `PLCDataIO` (Allen-Bradley: in-memory tags) and simulated QR/camera servers; runs two full cycles and prints the state trace, the state-2 cycle settings written, and the IO->FE messages. |
| `DryRun_IOServer_Fault_Scenarios.py` | Same harness, the non-happy paths, with automatic PASS/FAIL checks (exit code 1 on failure): (A) camera NOT OK -> OK=False/Done=True, back to the picture state, retried, cycle completes; (B) rejected QR -> IOServer stays in WRITE_QR_CODE and writes nothing to the PLC (current behaviour, see CHANGES section 9), the accepted code then proceeds with its own side/model; (C) emergency abort mid-cycle -> ABORT to QR server, emergency to FE, the 7 key queues cleared, all 37 per-cycle handshake tags (38 on Siemens, with the rotation-done bit) reset (explicit list), QR re-armed, and a full cycle afterwards; (D) state-2 cycle settings: Allen-Bradley side/model + setpoints from the properties, Siemens side + the 5 settings in force in `machine_settings` (no model), the settings written published to Redis for the DB record, and (Siemens) a settings change made mid-cycle written in the next cycle; (E) values before Done: every Done=True after its OK, state-2 settings before QRCodeCheckOK/Done; a setting the PLC refuses (or, Siemens, no settings in the database: nothing written) -> QRCodeCheckOK=False, Done=True, back to the QR code, re-scan then runs the cycle. (F) abort from the frontend (fe2io.q) part-way through a cycle and while waiting for a camera result: back to the QR code at once, QR scan stopped, handshake tags reset, no emergency echoed to the frontend, a late camera answer ignored, then a full cycle. (G) result handshake: OK -> OK=True, Check=False, Done=True, (0.4 s) Done=False, OK=False, then the next state; NOT OK -> OK=False, Check=False, Done=True, (0.3 s) Done=False, Check=False, then back to the picture state; no picture without a 2HB press; a press right after a NOT OK is acted on (field issue 1); torque Set/Value and press Done reset `plc.handshake.reset.delay.sec` after reading; a camera answer for another picture is ignored. (H) end-of-cycle message to the camera; (I) PLC connection lost / restarted (between steps the side written in state 2 is the fallback reference). (J) camera answer timeout (NOT OK after `plc.camera.answer.timeout.sec`, late answers ignored by request id), camera / database / frontend / heartbeat server / Redis down (simulated heartbeat server, `_plc_sim.HEARTBEAT`); E3 / E4 / E5: settings not available, refused, or not held by the PLC after the write (read back) -> the cycle goes ahead with the PLC's settings. (L) the IOServer heartbeat DEAD while the read loop, write loop, emergency monitoring or connection-status toggle thread is stuck (L1-L4). (K) an abort while a handshake write is on its way: the write lands first, then the reset (Done not left True); the connection-status toggle goes on during an abort. `COSTHETA_DRYRUN_SCENARIOS=J` runs one group. |

Needs Redis and PostgreSQL; vendor from `COSTHETA_PLC_VENDOR`. |

Needs Redis, PostgreSQL, a display (Linux: `xvfb-run`). |

## Allen-Bradley or Siemens

`DryRun_IOServer_Two_Full_Cycles.py`, `DryRun_IOServer_Fault_Scenarios.py` and `DryRun_All_Servers_Integrated_Cycle.py`
run the IOServer (`costhetaio/commonplc/PLCIOServer.py`) with the PLC make of `plc.vendor` (siemens in the repo's
properties file), or of `COSTHETA_PLC_VENDOR` when set. With siemens it uses `SiemensPLCDataIO` on a simulated S7 data block
(`_plc_sim.py`): every tag goes through the real `SiemensPLCDataIO` and pyS7 backend, its DB500 address and the S7 byte
encoding. Only the driver below the `PLCDataIO` (pycomm3's LogixDriver, pyS7's S7Client) is simulated.
`COSTHETA_WRITE_TRACE=<file>` also appends every PC write to that file, in order (to compare two versions of the
IOServer). `_plc_sim.ERRORS` holds tag names the simulated driver fails on (pycomm3: error in the result;
pyS7: exception). PowerShell:

    $env:COSTHETA_PLC_VENDOR = "siemens"; python test/machine1_dryrun/DryRun_IOServer_Fault_Scenarios.py; Remove-Item Env:COSTHETA_PLC_VENDOR
